# Benchmark Integrity

How rtl-mosaic resists "LLM slop" — i.e., how we ensure the benchmark measures the model under test rather than the labeler-LLM that built it.

## Problem sources

Every problem in the benchmark is drawn from **ChipBench** (UCSD/Columbia, 2026), a public peer-reviewed benchmark with reference Verilog implementations and testbenches. ChipBench was authored before any of the work in this repo and is not LLM-generated. Counts in the current evaluation:

- `cpu_ip` (RISC-V CPU sub-blocks): 9 problems, all 9 labeled.
- `self_contain` (single-module problems): 16 of 30 labeled (Prob000, 006, 011, 013, 015, 017, 023, 024, 025, 026, 027, 028, 030, 031, 032, 033, 034).
- `not_self_contain` (hierarchical): 6 problems, used in scratch baseline only, not in the routing eval.

VerilogEval, RealBench, and HDLBits are noted as future task sources but are not currently used.

## Reference Verilog and testbenches

For every problem the `_ref.sv` (reference implementation) and `_test.sv` (testbench) ship with ChipBench. We do not generate these. The Icarus simulation pass/fail signal in the scratch baseline comes from running the LLM's output against the upstream testbench.

## Gold labels

Each gold label in `eval/gold_labels.py` is hand-written by Matt after reading the problem's spec and reviewing the corpus. Each entry has three fields: `expected_subblocks` (corpus IP IDs that ought to be reused), `expected_kinds` (per-role REUSE_IP / GENERATE decisions), and `rationale` (one prose sentence). Empty `expected_subblocks` is a valid label and used for problems where nothing in the corpus fits.

Currently one annotator (Matt). Inter-annotator agreement is an open limitation tracked in `CONTEXT.md` and in the report's self-assessment.

## IP corpus

The 30-IP corpus in `mcp/corpus/` is hand-written. Every IP carries a parameterizable Verilog implementation in `modules/<id>.sv` and an Icarus self-test in `tests/<id>_test.sv`. All 30 self-tests pass under `iverilog -g2012` (re-run as part of any release check). Categories: memory, datapath, counter, sequence, primitive, clock.

The IP code itself was written for this project, but every architectural pattern is standard textbook (RISC-V ALU, Gray-code counter, Johnson counter, LFSR with parameterizable taps, dual-port RAM, ripple and carry-lookahead adders). Each IP in `catalog.json` carries an explicit `license` field, all MIT.

## What we do not use LLMs for

- We do not use an LLM to generate problems.
- We do not use an LLM to generate reference Verilog.
- We do not use an LLM to generate testbenches.
- We do not use an LLM to generate gold labels.

## What we do use LLMs for

- **Planner output.** This is the input to our metric. The whole point of the benchmark is to measure how the planner LLM decomposes specs into REUSE_IP and GENERATE subblocks, so the LLM's planner output is the thing under test, not a confound.
- **Codegen for GENERATE subblocks.** When the end-to-end harness assembles a TopModule, an LLM writes the bespoke logic for any subblock the planner tagged GENERATE. This is a separate path from the routing eval that produces the headline numbers.
- **Integrator wiring.** When stitching corpus IPs together at the TopModule level, an LLM emits the wire connections. This also lives in the end-to-end harness, not the routing eval.

## Why this matters

A benchmark whose problems and labels are generated by one LLM and used to score another LLM measures the labeler-LLM as much as the model under test. If the labeler and the test subject share training data or share systematic biases, the benchmark loses signal. Holding the problem set, reference implementations, testbenches, and gold labels constant and human-authored isolates the planner LLM as the single moving piece in our protocol.

## Reproducibility checks

- IP self-tests: `cd mcp/corpus && for f in modules/*.sv; do iverilog -g2012 -o /tmp/sim $f tests/$(basename $f .sv)_test.sv && vvp /tmp/sim | grep -E 'PASS|Mismatches: 0'; done`
- Gold count: `python3 -c "from eval.gold_labels import GOLD; print(len(GOLD))"` should print 26.
- Routing eval reproducibility: `python3 eval/multi_routing.py --workers 16` regenerates `results/multi_routing/summary.json` from scratch in under ten minutes wall-clock at 16-way concurrency.
